# zoria-sandbox

Іграшкова модель турніру **ZORIA** — щоб зрозуміти механіку до того, як видадуть
справжній SDK. Гра тут вигадана й примітивна; важливе не вона, а **обв'язка**:
протокол, тіки, дедлайни, Накази, реплеї та арена. У справжньому турнірі гра буде
інша, а ця обв'язка — та сама.

Потрібен лише Node 22+. Ніякої збірки: типи стрипає сам Node.

```bash
npm install
npm run match    # один матч по WebSocket
npm run drop     # те саме, але з обривом зв'язку посеред матчу
npm run arena    # 800 матчів без мережі: вінрейт із похибкою
npm run orders   # «Тиждень 1»: накази проти наказів, без живих ботів
npm run tune     # перебір ваг стратегії на арені
npm run viewer   # зібрати viewer/index.html з останнього реплею
```

## Що де лежить

| Файл | Що це в термінах анонсу |
|---|---|
| `src/engine/game.ts` | **Движок** (`@contest/engine`). Чисті правила, без мережі. Правила = код, а не PDF |
| `src/engine/server.ts` | Сервер-суддя: тіки, дедлайни, перехоплення Наказом, `RESUME` |
| `src/engine/order.ts` | Інтерпретатор **Наказу**. Виконується на сервері — тому й YAML, а не JS |
| `src/bot/transport.ts` | **Транспортний шар**: heartbeat, реконект із бекофом, resume, дедлайн-гард |
| `src/bot/strategy.ts` | Стратегія живого бота. Ваги підібрані, не придумані |
| `src/bot/orders/*.yaml` | Накази — декларативний автопілот на випадок обриву |
| `src/arena.ts` | Локальна арена: вінрейт із довірчим інтервалом |
| `src/arena-orders.ts` | Арена самих Наказів — модель Тижня 1 |
| `viewer/` | Реплей-в'ювер: видно, хто керував на кожному тіку |

## Три речі, які тут видно вживу

**1. Один матч нічого не доводить.** Перша версія стратегії виглядала розумною
й давала **30%** вінрейту. Після перебору на арені — **60.9% ± 3.4**, і 57–59%
навіть після зсуву констант. Дізнатись про це можна було тільки вимірюванням.

**2. «Розумні» правила зазвичай шкідливі.** У Наказі правило «тікай від суперника»
дало **21%** проти простого «біжи по ресурс» (50%). Кожен хід убік від ресурсу
коштує тік, а тіки — це і є рахунок.

**3. Дзеркало має бути справжнім.** Якщо для однієї сторони брати парні сіди,
а для іншої непарні — це не дзеркало, а два різні набори світів: бот проти
самого себе показує 48.8% замість 50%, і ти «покращуєш» шум. Правильно —
кожен сід грати двічі, зі зміною сторін.

## Два баги, на які варто подивитись окремо

Обидва відтворені тут навмисне — вони з того самого класу, що ловлять
турнірні «присяги».

**Стейлові таймери дедлайну** (`src/engine/server.ts`). Таймер тіку N спрацьовував
уже під час тіку N+8 і гасив `pending`, що належав чужому тіку. Той тік не міг
завершитись ніколи — матч намертво вставав. Таймер зобов'язаний перевіряти, що
гасить саме свій запит. Поки тіки летіли за мілісекунди, баг був невидимий, і
виліз лише коли сервер почав тримати фіксований темп.

**Результат у мертвий сокет** (`src/engine/server.ts`). Сервер відправляв `RESULT`
і одразу закривався. Бот, який саме перепідключався, його не отримував і висів
у реконекті вічно. Лікується збереженням результату + пільговим часом на закриття.
